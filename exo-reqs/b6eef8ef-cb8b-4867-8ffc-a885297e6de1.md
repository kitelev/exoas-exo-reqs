# req(exo): `apply` and `resolve-buttons` name the files the loader skipped — and say so when the TARGET itself was skipped

**Job story.** When a command refuses an asset («Precondition not satisfied») or shows it no buttons, and the real cause is that the vault loader dropped that file (e.g. the #2997 invariant «Optional property … is present but empty»), I want the command to say so, so I fix the file instead of hunting a precondition bug.

**Origin.** GitHub kitelev/exocortex#4274; founder decision 2026-09-26 (post-window interview): «ремонт данных + видимость», the loader invariant stays as is. Sibling of req `81cd5d1f-6466-47c9-99cd-8fe9f9b500a3`, whose Non-goals deliberately left `apply` / `resolve-buttons` to «a separate decision per command» — this is that decision for these two.

## Scenarios

```gherkin
Scenario: apply names its target as skipped before the refusal it causes
  Given a vault where "<target>" has an empty optional property, so the loader skips it
  When I run `apply <command> <target>` (default full parse)
  Then stderr says "<target>" itself was skipped by the vault loader, with the loader's reason
  And the precondition refusal still follows

Scenario: apply lists the skipped files even for a healthy target
  Given the same vault
  When I run `apply <command> <healthy-target>`
  Then stderr carries the skipped-files notice (path + reason, capped like `query`)
  And no line claims the healthy target was skipped

Scenario: resolve-buttons keeps --json stdout a single document
  Given the same vault
  When I run `resolve-buttons <target> --json`
  Then stdout parses as one JSON document, identical in shape to a vault without skipped files
  And stderr says "<target>" itself was skipped, with the reason

Scenario: the cache path names no cause it does not know
  Given the same vault and a triple cache
  When I run `apply <command> <target> --use-cache`
  Then stderr says "<target>" contributed no triples and that the cache does not record why

Scenario: a clean vault prints nothing new
  Given a vault the loader skips nothing in
  When I run `apply` or `resolve-buttons`
  Then stderr carries no skipped-files line
```

## Mechanism

`skippedFilesNotice` (already used by `query`) plus a new `targetSkippedNotice(loaded, vaultRelative)` in `packages/cli/src/cache/loadVaultTriples.ts`, written to stderr by `apply` (after the load, and once per target before its execution) and by `resolve-buttons` through its `load.log` channel (stderr).

## Non-goals

- `classes`, `run-query`, `validate-schema`, `CandidateShaclValidator` stay silent (separate decisions, as req 81cd5d1f names them).
- The #2997 loader invariant and the cache format are untouched (founder decision: repair the data instead).
- Repairing the two known files is a data task (Clean Properties), not part of this requirement.
