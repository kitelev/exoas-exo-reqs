# req(exo): the plugin's «Resolve sync conflicts» does not answer ✅ over pinned paths

## Job Story

When I run «Resolve sync conflicts» in Obsidian on a vault whose pins are not conflicts (typically incoming changes a push-only run deferred), I want the notice to say how many paths are pinned and what they are waiting for — the same thing `exosync quarantine list` already says since req c0b0e8bf — instead of «No open sync conflicts — nothing to resolve ✅».

## Statement (Gherkin)

```gherkin
Given materialized AssetSpaces with no open conflict and no duplicate uids
And pinned paths that are not conflicts (e.g. two remote-pending, one local-withheld)
When the user runs «Resolve sync conflicts»
Then the notice names the pinned count and the count of each kind present
And it recommends running Sync
And it does not claim «nothing to resolve ✅»

Given no open conflict, no duplicate uids and no pins
Then the notice is «No open sync conflicts — nothing to resolve ✅» (unchanged)

Given no open conflict but duplicate uids
Then the duplicate-uid notice keeps priority (unchanged)
```

## Why

UI↔CLI / Desktop↔Mobile parity of req c0b0e8bf (kitelev/exocortex#4391, v16.256.0). The core (`QuarantineResolver.classifyPins`) is shared; the plugin's empty state still hid the pins. Issue kitelev/exocortex#4392, task c5f303ba.
