# req(exo): the `service_call updateProperty` grounding SERIALISES the value it writes

## Job Story

When I press a button whose grounding is a `service_call updateProperty` — set a
result, set a planned start — and I type free text into the modal, I want the
text to come back out of the file unchanged. Today it does not.
`createUpdatePropertyService` hands `userInput.value` straight to
`FrontmatterService.updateProperty`, whose contract is "already-formatted YAML",
so `PR #42 merged` lands bare and every YAML reader keeps `PR` and treats
` #42 merged` as a comment — the same silent truncation #4405 described, at
rc 0. Three shapes are worse than truncation: `fix: broken parse`, `- item` and
a multi-line value make **js-yaml throw on the whole frontmatter block**, so the
asset collapses to nothing at every read.

This is the sibling-writer half of the class #4424 closed on the `property_set`
path. It is NOT the same fix: #4424 needed an ORIGIN discriminator because one
variable there carries both author-written YAML and substituted user text. On
this path it does not — measured, not assumed (see the covers clause) — so the
simpler fix is the correct one.

## Statement (Gherkin)

```gherkin
# --- the defect ---

Given a `service_call updateProperty` grounding whose `userInput.value` is a
  string carrying YAML-significant characters (` #`, `: `, a leading
  indicator, leading or trailing whitespace, a newline)
When the service runs
Then the value loaded back by js-yaml equals the string byte for byte

# --- the live corpus: zero bytes change ---

Given a value that needs no quoting (a timestamp `2026-07-25T09:00:00`, a
  date, an `obsidian://` IRI, a pre-quoted wikilink `"[[uid]]"`, a number, a
  boolean)
When the service runs
Then the written line is byte-identical to the revision before this
  requirement
# All six live groundings that reach this factory pin a timestamp / date
# property, so the authored corpus changes by zero bytes.

# --- the ORDER, which is a requirement and not a preference ---

Given `userInput.value` is a BARE wikilink `[[uid]]`
When the service runs
Then it is REFUSED loudly, with the same contract req 29e0d1b6 teaches on the
  `property_set` path, and NOTHING is read or written
# serializeYamlScalar quotes a bare [[uid]] on its leading `[`, so serialising
# BEFORE the guard makes the guard blind and turns a loud refusal into a
# silent successful write.

# --- the non-string channel, measured ---

Given `userInput.value` is an ARRAY
When the service runs
Then it is written as a multi-line YAML list, byte-identical to the revision
  before this requirement
# serializeYamlScalar on a non-string returns String(value), which would
# collapse ["[[a]]","[[b]]"] to the single line `a,b`. The
# `typeof value === "string"` guard is what prevents that.

# --- the engine's own output is NOT serialised twice ---

Given the `setStatus` grounding, whose factory builds `"[[<uid>]]"` itself
When the service runs
Then the written line is byte-identical to the revision before this
  requirement

# --- addressability ---

Given a mutant that removes the serialisation
When the matrix runs
Then exactly the round-trip axes redden and the byte-identity axes stay green

Given a mutant that drops the `typeof value === "string"` guard
When the matrix runs
Then exactly the array axis reddens

Given a mutant that moves the serialisation BEFORE the unquoted-wikilink guard
When the matrix runs
Then exactly the refusal axis reddens
```

## Verification

- `packages/cli/tests/unit/services/updateProperty-serialise-4520.test.ts` —
  the factory driven end to end through the real `FrontmatterService` and a
  filesystem stub: each YAML-significant shape round-trips through `js-yaml`;
  the live-shape control group stays byte-identical; a bare wikilink is refused
  with nothing written; an array is still written as a list.
- ⛔ The axes do NOT live next to the subject. No workflow runs jest for
  `packages/services` (`test-ci-batched.sh` drives exactly three configs —
  obsidian-plugin, cli, core); axes placed there sit outside every gate. They
  live where `test-coverage-cli` gates them, beside the #4513 axes of the same
  factory.
- revert-verify — one mutant per guard of the diff, enumerated from
  `git diff -U0`, each reddening an addressable set; the matrix is what shows
  it, not prose (`integration-test-revert-verify` §A141).
- req 29e0d1b6's own suite and req 992f0a75's harness re-driven on this tree:
  the shared `isUnquotedWikilink` relocation must leave them byte-identical.

## Approval

Approved by sanction, not by the founder. Issue `kitelev/exocortex#4520` states
the design and the decision rule verbatim — "if `value` here is only ever
caller/user input (as `:617` suggests) then plain `serializeYamlScalar` is
enough and no discriminator is warranted — the simpler fix is the right one.
Measure before copying #4424's shape" — and the measurement reported in the
covers clause resolves it. `req__Requirement_approvedBy` is deliberately EMPTY:
it names WHO approved, and putting an assistant identity there would fabricate
a human approval (`decision-surface-must-derive-from-mechanism`).
