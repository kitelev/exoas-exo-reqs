# req(exo): property_set serialises a SUBSTITUTED value, leaves an AUTHORED one verbatim

## Job Story

When I press a button that writes a property from something I typed — a note, a
result, a free-text comment — I want what I typed to come back out of the file
unchanged. Today it does not: `property_set` hands an untyped,
non-string-semantic value to `updateProperty`, which writes verbatim, so
`PR #42 merged` lands bare and every YAML reader keeps `PR` and treats
` #42 merged` as a comment. Nothing fails; the command reports success.

The obvious repair — route that branch through `serializeYamlScalar` — was
implemented, measured wrong and reverted: it quotes the deliberate flow array
`["[[ems__Task]]"]` of the multi-class convert path on its leading `[` and
breaks req `675cb0ab` axis K13. Both values are plain strings at the write
site. What separates them is not their shape but their ORIGIN — YAML an author
wrote in the grounding, versus text a substitution put there — and origin is
not recoverable from the bytes. So it is recorded where the value is produced.
