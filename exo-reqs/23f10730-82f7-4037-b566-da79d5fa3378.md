## Job Story

When I open a daily note, I want the rows of a named query (the first one: «Эпизоды дня») drawn
as a table where the Layout puts it, because today any new view of a page needs code (RFC 9821a379
§Проблема). The core half shipped in v17.16.0 (req ddd9b7f1): the block kind, the block → Layout
link, the Layout choice and the projection order. This is the plugin half: the provider, the
cells, «индекс стабилен», the unset-token bypass, the error isolation and the re-render after a
deletion (RFC AC10, second half — the founder's decision of 2026-10-30).

## Statement (Gherkin)

```gherkin
Given a page whose Layout carries a query-table block naming the query Q (by uid)
  and the index is stable
When the page is rendered
Then the block runs Q through NamedQueryRunner with $currentAsset = the IRI of the page
  and its columns are Q's SELECT projection in the order Q declares it (result.variables), not the binding order
  and a cell holding the IRI of an existing vault asset (percent-decoded path) is a link whose text is the
    asset's display name (the exo__DisplayNameSpec resolver the Relations table uses, vault rules included);
    clicking it opens the asset in-app
  and any other IRI is text (its Obsidian name); a literal is its lexical form, verbatim (never through Date);
    an unbound cell is empty
  and at most query__TableBlock_limit rows are shown; when more came back, the footer says «показано N из M»
  and the footer names the query time «запрос X мс» (label lookup + query + cells)
  and an empty result shows query__TableBlock_emptyText

Given no complete index exists yet (cold start: the eager walk ran over a still-parsing metadataCache)
  or a full rebuild (refresh) is in flight
When the page is rendered
Then the block shows «Загрузка…» — never the empty text — and does not run Q
  and when the index becomes stable the rows appear in the same block without another render
  and if the authoritative first walk FAILED the block says «Индекс хранилища не построен (<reason>) —
    строки появятся после переиндексации» instead of loading forever
# A complete index = the eager walk over an ALREADY resolved metadataCache (marked where the plugin reports
# «indexing complete», #3472) OR ANY full rebuild that completed (post-`resolved`, profile switch,
# link-label refresh) — so a later successful rebuild recovers a failed first walk.
# Incremental updates (per-file swap, reindexPathsFromDisk) do not make it unstable.

Given a page render of root R started (every render of R — with or without a Layout — begins a page of R)
When an answer of an EARLIER render of R arrives, even if that earlier render reached the block later,
  or R was on the page when its render started and has been removed since (another note was opened)
Then that answer is not painted and, if it has not been asked yet, Q is not run
  and a page left while its block waited for a stable index never runs Q
# Per root: renders of two pages run concurrently, and the page that was left must not silence the visible one.

Given Q's body still carries a token $x after $currentAsset is substituted
  (outside string literals, IRIs and comments — "$1" in REPLACE is not a token)
When the block runs Q
Then Q is not evaluated and the block says «Запрос «<label of Q>»: в запросе не задан $x»
# Bypass of ems__Bug 2bc09942: the engine reads $x as an unbound variable and a comparison with it
# lets every row through. NamedQueryRunner.run(…, { refuseUnsetTokens: true }) is opt-in — runScalar
# and CLI run-query behave as before.

Given Q is missing or has no sparql block, or its body is an UPDATE or a syntax error, or it is an ASK,
  or building the cells fails
When the block runs Q
Then the block shows the problem named by Q's label (or its uid when the label is unknown or its lookup fails)
  and the other blocks of the Layout and the page sections below still render

Given any block of a Layout throws while it is drawn, or the computation the daily blocks share throws
When the page is rendered
Then that block (each daily block) shows «Блок «<title>»: <message>» in its own place, the next blocks still render
  and render() does not throw

Given a pn__DailyNote whose Layout carries only a query-table block
When the page is rendered
Then the day's task table is rendered exactly as without a Layout (same call, same options)

Given a page with a query-table block is open (desktop or mobile)
When a file of the vault is deleted in Obsidian (vault "delete") and the deletion changed the index
Then once the change is done the open page is re-rendered (debounced 150 ms under one key:
  deletions applied within 150 ms of each other re-render once) and the block re-runs its query
  — "done" = the file's triples removed, or the full rebuild a deleted reified statement or
  FileSpace declaration needs has completed
  and a deletion that lands during a full rebuild waits for it, then removes the triples that
  rebuild read of the file before it was deleted (unless the path exists again), then re-renders
  and deleting a file without triples (an attachment, an excluded folder) or editing a file
  does not re-render
# The founder's decision of 2026-10-30 (RFC AC10, second half). A deletion changes no other file's
# frontmatter, so metadataCache "changed" does not fire, and "resolved" re-renders once per load.
# A deletion pulled by ExoSync is already followed by the post-sync reindex re-render.
```

## Non-goals

- Re-rendering the open page when a file is RENAMED — the founder's decision covers deletion; whether
  another path re-renders the page after a rename was not checked.
- An edit or rename that lands during a full rebuild (the same early return as the deletion had) —
  ems__Bug `fd19f7d5`.
- `$currentClass` — the provider passes only `$currentAsset`; a query using `$currentClass` is
  refused as an unset token (named in the block). So is a `$x` the query binds itself — write `?x`.
- After a full rebuild fails — in the pause before its retry, or for good once its retries are
  exhausted — the store is left cleared (or, when the rebuild failed after loading the triples,
  without the inferred ones) and until the next successful rebuild only per-file updates refill it,
  while the index still counts as stable (a complete index is never revoked); a block drawn or woken
  then shows its empty text or an incomplete table. Closing it needs a «store incomplete» state on
  top of the retries.
- `UniversalLayoutRenderer.refresh()` re-renders the root it last drew into without checking that the
  root is still attached; when that root was removed and no new one drawn (edit mode, the Layout hidden
  by a setting, no metadata container, Obsidian re-rendering the preview before the observer redraws),
  such a refresh queries once and paints into the detached root (a cost, not a wrong page).
- The three vault assets of «Эпизоды дня» and AC6 / AC13 — phase 3 (`193c556b`).
- CLI `run-query` column order (idea `cb16b1b9`) and an unset-token refusal in the CLI.
