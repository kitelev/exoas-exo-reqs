## Job Story

Когда мне нужно **дописать** абзац в тело существующего ассета, я хочу прочитать текущее тело
той же командой, которой буду его писать — потому что `set-body` перезаписывает тело **целиком**,
и без чтения любая правка превращается в «перепиши по памяти», то есть в молчаливую потерю всего,
чего автор не помнит.

Сегодня у CLI есть только сторона записи: `set-body` (issue #3943) и `create --body-file` (#3744).
Читающего верба нет вовсе — замер `--help` на v16.x по `body|show|cat|read|print` даёт единственный
body-верб `set-body`.

## Замеренная мотивация (2026-09-27, личный Telegram-ассистент)

Инцидент воспроизведён целиком и стоил перезаписи тела концепта по памяти.

Ассистент — headless-сессия Claude Code с `cwd=/private/tmp/kitelev-assistant-cwd` и **без
`--add-dir`**, поэтому файлы vault лежат вне разрешённого рабочего дерева. Транскрипт хода
08:53 показывает четыре попытки и четыре отказа:

| канал | отказ |
|---|---|
| `find <vault>/…` | `blocked … may only search files in the allowed working directories for this session: '/private/tmp/kitelev-assistant-cwd'` |
| `Glob` | `No such tool available: Glob` |
| `Read <абсолютный путь>` | `requested permissions …, but you haven't granted it yet` |
| `cat <путь>` | `blocked … allowed working directories: '/private/tmp/kitelev-assistant-cwd'` |

Граф тоже не помогает и не должен: замер по концепту `b3ca6287` даёт 10 триплов, все из
frontmatter; проза тела в триплы не эмитится вовсе (из тела в граф уходят только wikilink'и
через `exo__Asset_bodyLink`).

⇒ у потребителя не осталось **ни одного** канала чтения, а `set-body` перезаписывает целиком.
Ассистент переписал тело по памяти и сам сообщил об этом пользователю. В тот раз обошлось —
прежнее тело он писал сам четырьмя минутами ранее; для тела месячной давности та же ветка
уничтожила бы его без единого предупреждения.

Расширять файловый доступ (`--add-dir`) — обход dogfood-контура: персона учит работать через граф
и CLI, а чтение файлами открывает vault целиком. Правильный канал — **читать тем же путём, которым
пишешь**.

## Statement (Gherkin)

```gherkin
Given существующий ассет vault с frontmatter-блоком и непустым телом
When я запускаю `cli get-body <path> --vault <v>`
Then stdout содержит РОВНО тело — всё после закрывающего разделителя frontmatter, без самого блока
And код возврата 0

Given существующий ассет с непустым телом
When я подаю вывод `get-body` в `set-body <path> --body-file -`
Then set-body отвечает changed:false
And exo__Asset_updatedAt ассета не изменился
# round-trip инвариант: get-body и set-body режут границу frontmatter/тело ОДИНАКОВО,
# включая семантику хвостового перевода строки, которую set-body дописывает сам

Given ассет, у которого после frontmatter нет тела
When я запускаю `cli get-body <path>`
Then stdout пуст
And код возврата 0
# отсутствие тела — законное состояние, а не ошибка

Given существующий ассет с телом на кириллице
When я запускаю `cli get-body <path> --json`
Then stdout — один JSON-объект с полями path, bodyBytes, body
And bodyBytes равен длине тела в БАЙТАХ UTF-8, а не в единицах UTF-16
# та же ловушка, что закрыта в set-body: на кириллице расхождение ~1.5x читается как потеря данных

Given путь, ведущий за пределы vault
When я запускаю `cli get-body <path>`
Then команда отказывает с ненулевым кодом возврата и сообщением, называющим vault
# зеркало гварда set-body

Given markdown-файл без exo__Asset_uid
When я запускаю `cli get-body <path>`
Then команда отказывает с ненулевым кодом и сообщает, что это не ассет vault
# get-body читает только ассеты — как и set-body их только пишет

Given путь к несуществующему файлу
When я запускаю `cli get-body <path>`
Then команда отказывает с ненулевым кодом и сообщением "Target file not found"

Given любой из перечисленных исходов
Then файл ассета остаётся байт-неизменным
# get-body — read-only верб: он не пишет, не штампует updatedAt и не создаёт файлов
```

## Non-goals

- Тело в граф не эмитится — этот req ничего не меняет в парсере и в эмиссии триплов.
- Файловый доступ песочницы (`--add-dir`) не расширяется: цель ровно обратная — дать читающий
  канал, не открывая vault файлами.
- Частичная правка тела (append / patch / замена фрагмента) — отдельная работа; этот req даёт
  примитив чтения, из которого append собирается вызывающим как read → modify → set-body.
- Персона ассистента (правило «не перезаписывай тело по памяти») — отдельный носитель, не код.

## Verification

Binding — integration-тест CLI на реальном временном vault (как у `set-body`:
`packages/cli/tests/integration/set-body.integration.test.ts`), тег `@req:<uid>` в заголовке.

Несущая ось — **round-trip**: она одна запирает и разделение frontmatter/тело, и семантику
хвостового перевода строки, и то, что вывод пригоден как вход. Мутант, сдвигающий границу резки
на один символ либо срезающий трейлинг-newline, обязан её покраснить.
