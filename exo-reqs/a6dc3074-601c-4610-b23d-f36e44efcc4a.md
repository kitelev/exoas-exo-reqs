## Контекст

`ErrorHandler.handle(error: Error): never` принимает **один** аргумент. Пять call-site ExoSync передают **второй**:

| файл | строка | контекст |
|---|---|---|
| `exosync-parity.ts` | 401 | `{ command: "exosync-parity" }` |
| `exosync-sync.ts` | 574 | `` { command: `exosync ${direction}` } `` |
| `exosync-quarantine.ts` | 553 | `{ command: "exosync quarantine list" }` |
| `exosync-quarantine.ts` | 571 | `{ command: "exosync quarantine resolve" }` |
| `exosync-quarantine.ts` | 604 | `{ command: "exosync dedup-uids" }` |

Аргумент **молча отбрасывается**. Ошибка синка не сообщает, какая команда её произвела — ровно та информация, которая нужна, когда падает раунд по 24 репозиториям.

⛤ **Код ЗАЯВЛЯЕТ намерение, которого не выполняет.** Это хуже, чем отсутствие контекста: пять call-site выглядят как рабочая передача, и следующий автор скопирует форму, добавив шестой мёртвый вызов.

⛔ Компилятор молчал, потому что `packages/cli/src` не типизируется **нигде** (корневой tsconfig его исключает, esbuild типы не проверяет). Всплыло через ratchet #4074.

## Требование

`ErrorHandler.handle` принимает необязательный контекст и **печатает** его в обоих форматах вывода.

## Gherkin

```gherkin
Feature: an error says which command produced it

  Scenario: text output names the command
    Given an ExoSync command fails
    When ErrorHandler.handle is called with { command: "exosync push" }
    Then the printed message contains "exosync push"

  Scenario: json output carries the command as a field
    Given the output format is json
    When ErrorHandler.handle is called with a command context
    Then the emitted object has that command in a dedicated field
    And the existing fields keep their names and shapes
    # Consumers parse this object; renaming or reshaping what is already there
    # would be a separate, breaking change.

  Scenario: no context behaves exactly as before
    Given ErrorHandler.handle is called with one argument
    When the error is printed
    Then the output is byte-identical to the current behaviour
    # ~40 other call sites pass no context. Their output must not move.

  Scenario: a CLIError keeps its structured formatting
    Given the error is a CLIError with its own format()
    When a command context is supplied
    Then the structured formatting is preserved and the command is added,
      not substituted
```

## Почему полный цикл

Вывод об ошибке — user-facing. Альтернатива («убрать второй аргумент у пяти call-site») была бы exempt-чисткой, но она **стирает намерение** вместо его исполнения, а информация о команде при падении 24-репного раунда реально нужна.

⛤ Дискриминатор Step 0 (мутант на `origin/main`): убрать второй аргумент у всех пяти call-site — **ничего не краснеет**, ни компилятор (пакет не типизируется), ни тесты. Свойство не залочено ничем ⇒ полный цикл.

## Область

Только `packages/cli/src/utils/ErrorHandler.ts` и его call-site. Сигнатура расширяется **необязательным** параметром — существующие ~40 вызовов с одним аргументом не меняются ни по форме, ни по выводу.

Часть #4075 (дефект 3 из 3).
