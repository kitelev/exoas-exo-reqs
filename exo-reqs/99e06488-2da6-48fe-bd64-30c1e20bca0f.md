# Job Story

Когда обязательная проверка `requirements-trace` докладывает «✅ Active-gate OK», я хочу быть уверен, что она **что-то проверила**, — чтобы «нарушений нет» нельзя было спутать с «корпус требований до неё не доехал».

# Контекст

Блокирующий шаг `Active-requirement gate` (`.github/workflows/ci.yml`) — единственная всегда-включённая гарантия req-first SDD: активное требование обязано нести верификационную привязку. Его вход — отчёт `packages/req-audit`, который считает ассет требованием **по наличию предиката** `req__Requirement_status`, а не по классу (`audit.ts:400` — `if (metadata["req__Requirement_status"] === undefined) continue;`).

Отсюда следствие, инвертированное относительно интуиции: **исчезновение корпуса делает обязательную проверку ЗЕЛЁНОЙ, а не красной.** Переименование предиката, перенос требований из `exoas-exo-reqs` в другой репозиторий, неудавшийся `git clone` в шаге подготовки — любой из этих исходов даёт `requirementCount = 0` → `activeTotal = 0` → `activeViolations = []` → гейт печатает «OK» и выходит с кодом 0, а 161 активное требование теряет контроль молча.

## Замер (исполнением на `origin/main` f116f447, не рассуждением)

Реальный корпус (клоны `exoas-exo-reqs` + `exoas-ems-reqs` — ровно то, что клонирует CI):

| сценарий | requirementCount | activeTotal | activeViolations | блокирующий гейт |
|---|---|---|---|---|
| без изменений | 172 | **161** | 0 | exit 0 (верно) |
| корпус пуст (каталог без файлов) | 0 | 0 | 0 | ⛔ **exit 0 — «✅ Active-gate OK — 0 active requirement(s), all bound.»** |
| предикат `req__Requirement_status` переименован в 172 файлах | 0 | 0 | 0 | ⛔ **exit 0 — тот же текст** |

Гейт исполнялся не пересказом, а извлечением его собственного `node -e` блока из `ci.yml` и прогоном с `RUNNER_TEMP`, указывающим на отчёт.

⛤ У соседнего критерия `rampReady` этот пол **уже есть** и обоснован в комментарии дословно — «Requires p0Total > 0 so `--gate hard` fails-safe (blocks) on an empty / failed-to-clone reqs set rather than passing vacuously» (`audit.ts`). Требование распространяет ту же дисциплину на блокирующий active-gate, у которого её нет.

# Statement (Gherkin)

## Сценарий 1 — пустой корпус отвергается как сломанный вход

    Given аудит трассируемости отработал без ошибок
      And в собранном отчёте ноль активных требований
     When блокирующий шаг Active-requirement gate читает этот отчёт
     Then шаг падает с ненулевым кодом
      And его сообщение называет причиной сломанный ВХОД гейта, а не отсутствие находок

## Сценарий 2 — сообщение отказа не читается как норма

    Given корпус требований пуст либо предикат req__Requirement_status в нём не найден
     When гейт отказывает
     Then текст отказа называет оба возможных корня — пустой корпус и ненайденный предикат
      And текст явно говорит, что вход гейта сломан, а не чист

## Сценарий 3 — живой корпус проходит байт-в-байт как раньше

    Given в корпусе есть хотя бы одно активное требование
      And все активные требования несут верификационную привязку
     When блокирующий шаг читает отчёт
     Then шаг выходит с кодом 0
      And печатает прежнюю строку «Active-gate OK» с числом активных требований

## Сценарий 4 — предикат детекции остаётся единственным ключом

    Given у требования заменён exo__Instance_class на другой класс
      And предикат req__Requirement_status оставлен на месте
     When аудит собирает корпус
     Then требование по-прежнему попадает в корпус
      And порог активных требований не срабатывает

# Non-goals

- ⛔ Не менять условие `activeViolations.length > 0` — существующий инвариант остаётся байт-в-байт.
- ⛔ Не вводить ratchet-порог (`activeTotal < сохранённая базовая линия ⇒ отказ`). Он строже, но требует хранить число в репозитории и бампать его на каждом законном переводе требования в `Deprecated` — то есть заводит собственный источник ложной красноты и обслуживания. Порог «ноль» такого режима не имеет: `activeTotal = 0` не может наступить законно, пока хоть одно требование в силе (сегодня 161).
- ⛔ Не менять поле `clean` и код возврата самого аудита — иначе сместится семантика `--gate soft|hard`, к дыре отношения не имеющая.
- ⛔ Не переносить требования и не переименовывать предикат. Требование — страховка на случай, если это когда-нибудь сделают.
