# req(exo): код не пишет статус эффорта без TBox-инстанса (enum `EffortStatus` = зеркало онтологии)

## Job Story

Когда я меняю статус задачи/проекта — из CLI, из выпадающего списка плагина или кнопкой
дефолтного workflow — я хочу, чтобы записанное значение **резолвилось** в существующий
TBox-инстанс `ems__EffortStatus*`; иначе во frontmatter появляется висячий wikilink,
статус невыразим ни одним workflow, а ассет молча выпадает из любой выборки по статусу.

## Замер (что именно мертво)

Коммит `exoas-public@c35a660d` (2026-08-13) удалил из общей онтологии **9** ассетов,
из них **два** — значения перечисления, захардкоженные в коде:

| статус | UID | remote | vault-my / vault-tbank / vault-exodev |
|---|---|---|---|
| `ems__EffortStatusToDo` | `6a0e933a-6653-46f4-95ae-ed7508177c73` | 404 | отсутствует / отсутствует / отсутствует |
| `ems__EffortStatusAnalysis` | `cde3525c-57ea-4efc-b477-2e7e7ccd3a1e` | 404 | отсутствует / отсутствует / отсутствует |

Канарейка (`ems__EffortStatusTrashed`, `5d14f18d`): найден на remote **и** во всех трёх
vault ⇒ проверка жива, ноль не является артефактом сломанного запроса.

Взамен парковки в онтологию добавлен `ems__EffortStatusWaiting`
(`0610947c-6a62-41c8-9d44-7863d3ba3a8e`, присутствует), которого в коде нет.

⛤ **Постановка задачи (`2c83aea9`) называла только `ToDo`.** `Analysis` найден тем же
замером: удалён тем же коммитом, живёт в тех же пяти файлах, теми же строками.
Формулировка «enum остаётся зеркалом онтологии» выполнима только при снятии **обоих** —
поэтому требование покрывает оба, а не половину.

## Живые пути записи (пять, а не три)

1. `packages/cli/src/executors/BatchExecutor.ts` — `case "move-to-todo"` / `case "move-to-analysis"`.
2. `packages/cli/src/executors/commands/StatusCommandExecutor.ts` — `executeMoveToToDo` / `executeMoveToAnalysis`.
3. `packages/core/src/domain/constants/EffortStatusOptions.ts` — `EFFORT_STATUS_OPTIONS`
   (живой потребитель — `StatusSelectPropertyField` плагина, 4 обхода).
4. `packages/obsidian-plugin/src/domain/property-editor/PropertySchemas.ts` —
   `FALLBACK_EFFORT_STATUS_VALUES` **в UUID-форме** (`[[6a0e933a-…]]`, `[[cde3525c-…]]`),
   поэтому греп по `EffortStatusToDo` его не находит.
5. `packages/core/src/domain/defaults/DefaultWorkflows.ts` — `PROJECT_DEFAULT_WORKFLOW`
   несёт оба статуса как состояния и четыре перехода между ними.

Плюс `packages/core/src/services/GroundingExecutor.ts` — `STATUS_UID_BY_ENUM` отображает
оба enum-члена на удалённые UID (то есть `workflow_transition` резолвит их в мёртвые файлы).

## Судьба вербов `move-to-todo` / `move-to-analysis`

`packages/cli/src/program.ts:39` фиксирует: `Removed: batch, batch-repair, command,
dyncommand, exoql, convert, sparql`. Точки входа `batch` и `command` **уже удалены**,
а `BatchExecutor` / `CommandExecutor` не импортируются ниоткуда в `packages/cli/src`.
⇒ вербы **недостижимы** из CLI, а строки `| exocortex command move-to-todo | **Stable** |`
в `VERSIONING.md` — устаревшая документация, а не живой контракт.

Значит удаление — **не breaking change**, deprecation-цикл не требуется; посылка
постановки «он Stable — нужен deprecation-цикл» замером опровергнута.

Кросс-репо caller-check (`gh search code user:kitelev`): единственные внешние вхождения —
allow-list обёрток ботов в `kitelev/dotfiles` и проза; ни одного исполняемого потребителя
CLI-верба. `@req`-тег на файле `command-dry-run.integration.test.ts` принадлежит
req `cd33eff0` (про `rename-to-uid --dry-run`) — снятие двух строк параметризованной
таблицы его биндинг не трогает.

## Non-goals

- ⛔ **Не нормализовать** удалённый статус в живой (например `ToDo → Backlog`) на лету:
  миграция данных уже выполнена в vault-слое (`exoas-exodev@d75ef794`); код должен
  перестать порождать значение, а не переписывать чужое.
- ⛔ Не трогать фикстуры e2e-vault и прочие тестовые `.md` — они не пишут в пользовательский
  vault; их приведение в порядок ценности не несёт и раздувает диф.
- ⛔ Не приводить в порядок остальную устаревшую таблицу вербов `VERSIONING.md`
  (там числятся и другие уже удалённые `exocortex command *`) — отдельная работа.

## Приёмка

- `git grep 'EffortStatusToDo\|EffortStatusAnalysis' origin/main` → ноль вхождений
  в `packages/*/src`; UUID-формы `6a0e933a` / `cde3525c` там же → ноль.
- Revert-verify: возврат любого из удалённых значений в enum, в карту UID,
  в список выбора или в дефолтный workflow — краснит ровно свою ось.
