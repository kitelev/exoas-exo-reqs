# req(exo): `cli create --aliases` отказывает на списке, склеенном запятыми, вместо того чтобы принять его за ОДИН алиас

## Job Story

Когда я завожу ассет скриптом и пишу `--aliases "Стек,стек,LIFO,stack"`, я хочу получить отказ с
указанием правильной формы — а не молча созданный ассет с ОДНИМ алиасом, текст которого состоит из
четырёх слов через запятую; иначе ошибка вызова обнаруживается месяцами позже, при чистке словаря.

## Контекст

`--aliases` объявлен вариадическим (`<names...>`), то есть правильная форма — каждый алиас
отдельным аргументом. Строка `a,b,c` для Commander это ОДИН токен, и сегодня он принимается без
единого слова. Эмпирика: 8 ассетов словаря концептов несли алиас вида `Стек,стек,LIFO,stack`
(разбор — тикет `73d7304b`, данные починены отдельно); эмиттер установлен по транскрипту — вызов
`exocortex-cli create … --aliases "Стек,стек,LIFO,stack"`.

Отказ выбран вместо тихого разбиения сознательно: вариадический флаг УЖЕ даёт правильную форму,
поэтому разбиение скрыло бы ошибку вызова вместо того, чтобы её исправить. Это та же логика, по
которой `--property aliases=X` отклоняется, а не переписывается (req `869561bf`).

## Почему запятая БЕЗ пробела, а не любая запятая

Дискриминатор — запятая, за которой НЕ следует пробел: такова форма машинно-склеенного списка.
Человеческий алиас запятую-с-пробелом сохраняет (`Иванов, Иван`, `Ltd., Co.`) и обязан приниматься
без изменений. Тот же предикат уже выбран генератором проекции словаря
(`build-concepts-index.py`, 2026-09-14) на тех же данных — то есть правило не выдумано здесь, а
согласовано с уже действующим читателем.

## Statement (Gherkin)

```gherkin
Given вызов cli create с --aliases, один из элементов которого содержит запятую БЕЗ пробела после неё
When команда исполняется (в том числе с --dry-run)
Then она ОТКАЗЫВАЕТ с ненулевым кодом
And сообщение называет проблемный элемент и печатает правильную вариадическую форму вызова
And ассет не создаётся

Given вызов cli create с --aliases, где алиасы переданы отдельными аргументами
When команда исполняется
Then ассет создаётся и несёт КАЖДЫЙ из переданных алиасов отдельным элементом

Given вызов cli create с --aliases, элемент которого содержит запятую И пробел после неё
When команда исполняется
Then элемент принимается как ОДИН алиас без изменений (отказа нет)

Given отказ create на форме --property aliases=X
When печатается подсказка о выделенном флаге
Then подсказка несёт ВАРИАДИЧЕСКУЮ форму (--aliases <a> <b>), а не форму со списком через запятую
```

## Verification

`packages/cli/tests/integration/create-aliases-list-bb855bb2.integration.test.ts` — оси Y1-Y4,
production-shape (реальный `createCommand().parseAsync`), revert-verified: снятие гварда краснит

## Non-goals

- Разбиение списка вместо отказа (вариант (б) тикета) — отвергнуто выше.
- Другие самоуправляемые поля `create` (`exo__Asset_label`, `exo__Instance_class`) — их тихое
  игнорирование отслеживается отдельно (`ems__Bug` 43e41c8f), это требование их не касается.
- Валидация `--aliases` у других команд: носителей нет (единственный второй — `mcp/tools.ts`,
  он передаёт по одному алиасу).

## Отклонение от формы соседей, названное явно

Соседние требования (`869561bf`, `8eaae6a9`) несут в `exo__Instance_class` ДВА типа — `req__Requirement` плюс `flow__Requirement` (`62464150`, тип доски конвейера vteam). Здесь стоит только `req__Requirement`, и это не недосмотр: `exo__Instance_class` — guarded-свойство, `set-property` его отклоняет (предлагает `convert-to-task|convert-to-project`, к требованию неприменимы), а прямой `Edit` frontmatter блокирует dogfood-хук. Замер происхождения у соседей: `git log -S 62464150` по клону `exoas-exo-reqs` указывает на коммит `01c538f exosync: 165 change(s) (CLI)` — то есть тип приехал массовым синком, а не командой; штатного пути добавить его через CLI сегодня нет. На приёмку это не влияет: `requirements-trace` читает `req__Requirement`. Если тип нужен для доски — это отдельная операция, и её стоит сделать тем же путём, каким она делалась соседям.
