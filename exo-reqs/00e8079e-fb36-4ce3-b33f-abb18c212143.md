## Контекст

Ассет, чей `exo__Asset_label` парсится как `<prefix>__<LocalName>`, эмитится в граф **term-IRI**,
а не литералом. Если два ассета несут один и тот же такой label, они эмитят **один и тот же
term-IRI** — и любой джойн «предикат → его определение» раздваивается.

Замер (2026-08-17, CLI 16.223.0):

| vault | коллизий |
|---|---|
| vault-my | 3 |
| vault-tbank | 1 |
| vault-exodev | 1 |

В vault-my это `http://www.w3.org/2002/07/owl#sameAs` (эмитят `exo__ObjectProperty` `9d2128de`
**и** `concept__Concept` `3c6240a5`), `https://exocortex.my/ontology/lit#WebPage_url` (два ассета)
и один случай, где label сам является file-ссылкой (три ассета).

Наблюдаемое следствие — живой reified statement с `exo__Statement_predicate = owl#sameAs`
резолвится в **оба** определения:

```
owl#sameAs -> 3c6240a5
owl#sameAs -> 9d2128de
```

⛔ Сегодня это не проверяет **ничто**. Более того, существующий код от коллизии **защищается**,
а не сообщает о ней: `audit-ontology-imports.ts:871` группирует по UID с комментарием
«labels have had duplicates — R12». То есть явление известно, обойдено и невидимо.

⛤ Коллизия **не создана** канонизацией W3C-namespace (req `aceaa2cc`): до неё оба ассета эмитили
один и тот же ad-hoc IRI, то есть раздвоение было ровно таким же. Канонизация лишь сделала его
заметным.

## Границы (несущие, не косметика)

- Проверка касается **только** label, эмитируемых как IRI. Обычные (литеральные) label дублируются
  массово и легитимно: замер vault-my — **214** различных литеральных меток у >1 ассета
  (`Initiative`, `Idea`, `Area`, `Bug`, `OKR`…). Ловить их означало бы 214 строк шума вместо 3.
- Severity — **Warning**, не Violation: три существующие коллизии не должны делать vault
  non-conforming в момент отгрузки проверки. Решение фаундера, 2026-08-17.

```gherkin
Feature: term-IRI collisions are reported by validate schema

  Scenario: two assets emitting the same term-IRI produce a warning
    Given an asset labelled "owl__sameAs" typed exo__ObjectProperty
    And another asset labelled "owl__sameAs" typed concept__Concept
    When I run `exocortex validate schema --shapes-mode`
    Then the report contains a warning naming "http://www.w3.org/2002/07/owl#sameAs"
    And that warning names BOTH emitting assets
    And the warning severity is "sh:Warning", not "sh:Violation"
    And `conforms` stays true

  Scenario: a term-IRI emitted by exactly one asset is not reported
    Given exactly one asset labelled "rdfs__subClassOf"
    When I run `exocortex validate schema --shapes-mode`
    Then no collision warning mentions "rdf-schema#subClassOf"

  Scenario: duplicate PLAIN labels are not a collision
    Given two assets both labelled "Initiative"
    And neither label parses as <prefix>__<LocalName>
    When I run `exocortex validate schema --shapes-mode`
    Then no collision warning mentions "Initiative"
```

## Приёмка

- Revert-verify: убрать детекцию → сценарий 1 RED, сценарии 2-3 GREEN; вернуть → все GREEN.
- Негативный контроль обязателен: набор обязан краснеть, если проверка начнёт ловить
  литеральные дубли (иначе она отличается от «сообщать про всё» только на глаз).
- Прогон на живом vault-my: ровно 3 предупреждения, `conforms` не меняется, `violationCount` 0.
