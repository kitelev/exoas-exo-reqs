# req(exo): a DisplayNameSpec whose property parts all render empty declines — unless declining would print a bare UID

## Job Story

When every `exo__PrintedProperty` part of a spec renders EMPTY — the referenced year is
missing, the number was never set, the target does not resolve — the engine still returns
the spec's LITERALS glued together (`Q2-`, `2025-`, `-W`, `-`) and, carrying provenance
`spec`, that string overrides the asset's own correct `exo__Asset_label`. I want the spec
to decline in that case, so the name falls through to something that is actually a name.

The capability already exists — but only in **separator mode**
(`DisplayNameTemplateEngine.renderWithSeparator`: *"Every field empty → the affixes alone
are not a name"*). The plain path has no equivalent, and the live period specs do not use
a separator. This requirement makes the two paths agree, and locks the separator-mode half
too: a mutant removing that guard reddens **0 axes today**.

## Statement (Gherkin)

```gherkin
Scenario: every property part empty, the asset has a label
  Given a period__Month whose spec composes "{{Month_year}}-{{Month_monthNumber}}"
    And neither property resolves
    And the asset's exo__Asset_label is "June (period__Month) (DEPRECATED)"
  When its displayName is resolved
  Then the spec declines (render → null) and the label is what a consumer prints
# Today: "-" — a name made of one separator, outranking a correct label.

Scenario: every property part empty, no label, but the FILE is named
  Given a period__Week stored as 2025-W26.md with no exo__Asset_label
    And neither Week_year nor Week_weekNumber resolves
  When its displayName is resolved
  Then the spec declines and the basename "2025-W26" is what a consumer prints
# Today: "-W". 44 of the 51 live assets this requirement moves are exactly this shape.

Scenario: CONTROL — declining would yield a BARE UID, so the spec does NOT decline
  Given an asset with no exo__Asset_label whose basename is a UUID
    And a spec whose only property part renders empty, leaving literals such as "👥"
  When its displayName is resolved
  Then the spec still composes, and "👥" is printed
# The lesser evil, and the same judgement req 0f992e88 already made: a bare UID inside a
# title is the defect that requirement exists to prevent. 3 live assets, all of them
# affix-only specs whose property part is empty BY DESIGN.

Scenario: CONTROL — a spec with at least one non-empty property part is untouched
  Given a period__Quarter whose quarterNumber renders "3" and whose year renders "2025"
  When its displayName is resolved
  Then it reads "Q3-2025", byte-identically to today

Scenario: CONTROL — a spec with NO property parts at all is untouched
  Given a spec composed only of exo__PrintedLiteral parts
  When its displayName is resolved
  Then it composes exactly as today
# The rule keys on "every property part rendered empty", not on "the result is short":
# a spec that never had a property part has nothing to decline about.

Scenario: separator mode keeps its existing behaviour, now locked
  Given a spec carrying exo__DisplayNameSpec_separator whose every FIELD renders empty
  When its displayName is resolved
  Then the spec declines — as it already does, and as no axis currently checks
```

## Verification

- core unit — the plain path: declines when all property parts are empty, composes when
  any one is non-empty, and is inert for a spec with no property parts.
- core unit — the bare-UID control: no label + UUID basename ⇒ does NOT decline.
- core unit — separator mode: the existing guard, now with an axis and a mutant.
- core integration — production-shape through `PrintNameRuleService.initialize()` →
  `resolveWithProvenance()`.
- revert-verify — one mutant per guard of the diff, each reddening its own axis.
- live-corpus delta — measured BEFORE the wording was frozen, on a prototype over the
  three canonical vaults: **51 461 assets compared, 51 names change** — 44 label-less
  files gaining their own filename, 4 gaining their label, 3 that the bare-UID control
  above deliberately excludes (those 3 are why the control exists, not an afterthought).

## Refs

Issue #4303 and its two requirements — `0f992e88` (the composed name replaces a bare
linkpath) and `ff1482f2` (a part declares WHICH name it prints): this one is about the
spec's OWN name rather than a referenced one, and it reuses `0f992e88`'s judgement that a
bare UID is the thing never to fall back to. `1a6525eb` (`exo__PrintedProperty_format`,
date-only) is untouched.

NOT GOVERNED, named rather than silent: zero-padding a plain number (`2025-5` where the
label reads `2025-05`) is a separate question — `_format` is a date vocabulary, and
storing `"05"` as a string would push presentation into data. The 12 live period assets
whose data was simply missing were fixed as data on 2026-09-21 (6 quarters, 2 weeks,
2 months, plus a created `period__Year` 2022); this requirement is about the CLASS of
defect that survives those fixes.
