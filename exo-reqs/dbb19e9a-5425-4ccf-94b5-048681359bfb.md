# req(exo): `set-body` / `create --body-file` отказывают на теле, ведущий фрагмент которого — КОПИЯ frontmatter-блока

## Job Story

Когда я переписываю тело ассета скриптом и по ошибке подаю файл, вырезанный ВМЕСТЕ с frontmatter,
я хочу получить отказ с указанием, где резать, — а не молча записанный ассет с двумя блоками,
который годами выглядит целым для YAML-парсера, для Obsidian и для SPARQL.

## Контекст

Хаб программы `31c2bdee` нёс **два** frontmatter-блока: настоящий и сразу за его закрывающим `---`
устаревшую копию (16 строк, `updatedAt 2026-09-11T02:33:29`). Для YAML-парсера копия была телом,
Obsidian показывал её текстом, SPARQL читал первый блок и оставался верен — поэтому о ней никто не
сообщил; нашли чтением, сняли `set-body` 2026-09-13.

До-фиксный текст восстановлен из git-истории data-репо (`exoas-exodev@169e6846`, родитель коммита
починки `b8184ded`) и предъявлен осям **дословно**. Он дал два факта, которых тело тикета не
содержало: копия начиналась **без** открывающего `---` (его роль сыграл закрывающий фенс
настоящего блока), и она несла `exo__Asset_uid: 31c2bdee-…` вместе с
`exo__Asset_createdAt: 2026-09-10T10:17:11`.

Правдоподобный эмиттер — `--body-file`, которому подали файл, срезанный от ПЕРВОГО `---`
(`sed -n '/^---$/,$p'`). ⛔ Механизм появления замером **не установлен**: vault git-free, писателя
не назвать; требование закрывает поверхность записи, а не атрибуцию.

## Почему именно такой дискриминатор

Наивная формулировка «тело начинается с frontmatter-блока» **опровергнута замером**: на трёх
каноничных vault она отвергает **31 живой ассет** `[три каноничных, 52 079 ассетов с frontmatter,
2026-09-24]` — и каждый из них `exo__Template`, чьё тело **по назначению** и есть frontmatter-
заготовка (`exo__Asset_uid: $randomUUIDv4`). Отказ на них снёс бы весь шаблонный слой.

Копию от шаблона отличает **значение**, а не форма: копия несёт системную идентичность реального
ассета (корректный UUID в `exo__Asset_uid` либо настоящий ISO-таймстемп в `exo__Asset_createdAt`),
шаблон — плейсхолдер (`$randomUUIDv4`, `$nowTimestamp`, пусто). Узкий предикат отвергает
**0 из 52 079** живых тел и при этом отвергает реальный до-фиксный текст хаба.

⛤ Ведущий блок кончается на СВОЁМ `---`: цитата реального таймстемпа ниже по телу (ретро-заметка
об этом же инциденте) остаётся законной. `---`, за которым идёт не YAML-ключ, — тематический
разделитель, а не фенс.

## Acceptance Criteria (Gherkin)

```gherkin
Scenario: set-body refuses a body that leads with a frontmatter copy
  Given a body whose first non-empty line is `exo__Asset_uid: <a well-formed uuid>`
  When I run `set-body <path> --body-file <that file>`
  Then the command fails fail-loud naming the offending line
  And the target file is left byte-identical

Scenario: the refusal is the guard's, not the wikilink validator's
  Given the same body and `--skip-wikilink-validation`
  When I run set-body
  Then the command still refuses and the file is left byte-identical

Scenario: the copy is refused on every body source
  Given the same text passed inline via `--body`
  When I run set-body
  Then the command refuses it too

Scenario: a template body stays legal
  Given a body that is a frontmatter skeleton whose uid/createdAt are placeholders ($randomUUIDv4)
  When I run set-body
  Then the write succeeds

Scenario: a quote below the leading block stays legal
  Given a template body whose prose below its closing --- quotes a real ISO timestamp
  When I run set-body
  Then the write succeeds

Scenario: ordinary content stays legal
  Given a body starting with a heading, or carrying a real uid inside a ```yaml fence
  When I run set-body
  Then the write succeeds

Scenario: a thematic break is not a fence
  Given a body starting with `---` followed by prose that quotes a real uid
  When I run set-body
  Then the write succeeds

Scenario: create --body-file refuses the same copy and creates nothing
  Given a --body-file whose leading fragment is a frontmatter copy
  When I run `create --class <c> --label <l> --body-file <that file>`
  Then the command fails fail-loud and no asset is created
```

## Non-goals

- Атрибуция писателя копии (механизм появления не установлен — см. §Контекст).
- Починка уже испорченных ассетов: на момент поставки таких в трёх каноничных vault **0**
  (хаб починен 2026-09-13); детектор постфактум — это сам предикат гварда, применимый к корпусу.
- Отказ на копии, лежащей НЕ в ведущей позиции тела (цитата в прозе, ```yaml-фенс) — законный
  контент, см. §Почему именно такой дискриминатор.
