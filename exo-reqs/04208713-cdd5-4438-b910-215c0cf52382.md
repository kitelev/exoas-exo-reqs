## Job Story

When my knowledge is split across many EKA AssetSpace repos and a **definition-tier** property of an asset in AssetSpace A (`exo__Property_range` / `_domain` / `_cardinality` / `_minCount` / `_superProperty`, `exo__Class_superClass`, `exo__Ontology_imports` / `_admits`) references an asset that lives in AssetSpace B, I want `audit assetspace-depends` to flag that fact edge A→B as **uncovered** unless A's registry descriptor declares an `exo__AssetSpace_dependsOn` whose **transitive closure** contains B, so that the per-repo CI gate (`exoas-ci` → `resolve-deps` → merged vault → SHACL) can never pass trivially because a TBox it needs was silently not materialised (RFC `306dcb5c`, frame decided by the founder 2026-09-12: **coverage is one-sided and judged by closure**; `dependsOn` itself is *packaging* and may contain cycles; acyclicity is a property of the facts, checked by a separate detector, not by this verb).

## Resolution (three channels, matching the reference detector)

A referenced target resolves (1) by UID (`[[uid]]`, `[[uid|alias]]`), (2) by label/alias index (`[[prefix__Local]]` and bare `prefix__Local` strings, which the RDF engine emits as symbolic IRIs), (3) by basename/path. Non-reference values (`xsd:string`, integers, `URL`) are not facts. Repeatable `--also <vault>` unions several vaults into one index so an AssetSpace mounted in only one of the canonical vaults still resolves (the "pathless bare-UID" channel of `assetspace-cycle-detect.py`).
