# req(exo): `set-property` rejects an EMPTY value instead of silently writing `prop: ""`

## Job Story

When I mean to **clear** a property and reach for the tool I already use for writing one, I want the
CLI to tell me that clearing has its own command — so that I don't end up with a junk key
`prop: ""` that looks like a successful clear but is a new, empty property nobody asked for.

## Statement (Gherkin)

```gherkin
Given an existing asset that does NOT carry `ems__Effort_area`
When I run `cli set-property <path> --property ems__Effort_area --value ""`
Then the command fails with a non-zero exit code
And the error names `remove-property` as the way to delete a property
And the asset file is left unchanged (no `ems__Effort_area:` key was added)

Given an existing asset that DOES carry `concept__Movie_watched: true`
When I run `cli set-property <path> --input '{"property":"concept__Movie_watched","value":""}'`
Then the command fails the same way
And the existing value is left untouched (the guard did not overwrite it with an empty string)

Given an existing asset
When I run `cli set-property <path> --property concept__Movie_watched --value false`
Then the command succeeds
And the property is written as a bare `false` (the empty-guard must not touch legitimate values)

Given an existing asset
When I run `cli set-property <path> --property exo__DisplayNameSpec_separator --value " "`
Then the command succeeds
And the property is written as `" "` (a WHITESPACE-ONLY value is legitimate — see §Границы)
```

## Почему это req, а не bug-fix существующего

Активный `3800d995` («generic cli set-property sets an arbitrary non-guarded frontmatter property»)
описывает **запись значения** и guard-отказы по имени свойства. Пустое значение он **не упоминает**:
ни обещает отказ, ни исключает его. ⇒ по дискриминатору `/feature-sdd` Step 0 это **новое
поведение**, а не приведение кода к уже данному обещанию.

## Замер, обосновывающий полярность (сделан ДО формулировки)

| | |
|---|---|
| заголовков multi-value списков | 44 370 — ⛔ **не** пустые значения; наивный счётчик считает их пустыми и даёт 44 267 ложных |

⇒ пустое значение — **аномалия**, а не употребляемая форма; запрет не ломает существующий путь.
⛤ Топ-2 — multi-value свойства с пустым списком, то есть похоже на след ровно этого дефекта.

⛤ **Пере-замер 2026-08-23 дал 91, и расхождение объяснено, а не подогнано:** первый счёт брал только
**префиксные** ключи (`prefix__Name:`), второй — **все** ключи frontmatter, включая беспрефиксный
`aliases:` (**33** носителя). `91 − 33 = 58` ⇒ оба замера верны, у них разные знаменатели.
⚠ Ни один не меняет вывод, потому что решающее число другое: форма `key: ""` — **0 носителей**
в трёх vault (см. §Границы), то есть запрет не ломает **ничего существующего**.

## Границы гварда — ЗАМЕР 2026-08-23 (MemberArchitect, StageSpecification)

⛔ **Буквальная «восстановленная симметрия» с проверкой имени СЛОМАЛА БЫ 15 ЖИВЫХ значений.**
§«Где чинить» ниже предписывает вернуть симметрию с `property.trim().length === 0`. Дословный перенос
предиката на значение (`String(value).trim().length === 0`) отсекает и **значимо-пробельные**
значения — а они существуют и употребляются:

| форма значения во frontmatter | носителей в трёх vault | вердикт гварда |
|---|---|---|
| `key: ""` (пустая строка в кавычках) | **0** | ⛔ **ОТКАЗ** — это и есть предмет req |
| `key: " "` / `"  "` (кавычки + ТОЛЬКО пробелы) | **15** — `exo__PrintedLiteral_literal` 9 · `exo__DisplayNameSpec_separator` 6 | ✅ **ПРОПУСК** — значение значимое |
| `key:` без текста после двоеточия | 91 — `aliases` 33 · `exo__Asset_relates` 32 · `concept__Concept_related` 15 · `exocmd__Grounding_propertyDefault` 3 · `exo__Class_superClass` 3 · … | вне гварда (см. таблицу входов ниже) |
| `key: <только пробелы, БЕЗ кавычек>` | 0 | — |

⇒ **Граница: `value === ""` (СТРОГОЕ равенство пустой строке), НЕ `value.trim() === ""`.**

⛤ Пробельное значение здесь не аномалия, а **единственный документированный путь его записи**:
`create --property k=<значение>` срезает обрамляющие пробелы, поэтому запись разделителя предписана
именно через `set-property --value ' · '`. Гвард по `trim()` закрыл бы этот путь и сделал бы
`exo__DisplayNameSpec_separator` / `exo__PrintedLiteral_literal` неписуемыми ни одной командой.

⚠ Симметрия с проверкой ИМЕНИ восстанавливается **по духу** (обе стороны валидируются), но **не по
букве предиката**: у имени `trim()` уместен (пробельное имя свойства бессмысленно и в TBox не
резолвится), у значения — нет.

### Что гвард НЕ трогает — проверено `--dry-run` на CLI 16.234.0

| вход | текущее поведение | вердикт спецификации |
|---|---|---|
| `--input {"value":null}` | ❌ уже fail-loud: `--input.value must be a scalar … not null` | оставить как есть, гвард не нужен |
| `--input {"value":{}}` | ❌ уже fail-loud: `… not object` | оставить как есть |
| `--input {"value":[]}` | пишет `key:` (ключ без значения) | ⛔ **ВНЕ scope этого req**: пустой список — осмысленная форма, **65** живых носителей (`aliases` 33 + `exo__Asset_relates` 32). Round-trip `[] → null` — самостоятельный вопрос, здесь НЕ решается |
| `--value "   "` / `--input {"value":"   "}` | пишет `"   "` | ✅ пропуск — прямое следствие строгой границы |
| `--value false` / `0` / непустая строка | пишет голым `false` / `0` / строкой | ✅ пропуск — негативный контроль |

⛤ **Пере-проверено 2026-08-23 на CLI 16.234.0 (`--dry-run`, sha файла не изменился): дефект ЖИВ**,
причём **обеими** дверями — и `--property … --value ""`, и `--input {"value":""}` дают в превью
`ems__Effort_area: ""` и JSON-эхо успеха.

## Где чинить

`packages/cli/src/commands/set-property.ts`, `resolvePropertyAndValue`: обе ветки проверяют имя
(`property.trim().length === 0` → ошибка) и **не** проверяют значение. Симметрия нарушена — правка
её восстанавливает.

⛔ **НО предикат значения ≠ предикат имени** — см. §Границы: у значения он **строгий** (`=== ""`),
иначе фикс отнимет 15 живых значимо-пробельных значений. Дословный перенос `.trim()` = регрессия.

⛤ Проверено на `origin/main` (`096c7e6a`, 2026-08-21): обе ветки (`--input` и `--property/--value`)
валидируют **только** имя — `typeof property !== "string" || property.trim().length === 0` в
input-ветке и `options.value === undefined` в convenience-ветке. Место фикса точно, ветки две.

⛤ Ось revert-verify обязана быть **парной**: пустое ⇒ отказ **и** легитимное `false`/`0` ⇒ запись.
Без второй половины гвард, отсекающий любое falsy-значение, прошёл бы зелёным.

⛤ **Третья ось обязательна и парной её НЕ заменить:** `--value " "` ⇒ **запись**. Без неё
`trim()`-гвард (регрессия на 15 носителей) остаётся зелёным — обе первые оси он проходит.

## Homoiconicity Gate (профиль `/onto-rfc`, Phase 0)

- **Q1 — user-configurable семантика?** **НЕТ.** «Пустое значение отвергается» не есть поведение
  домена пользователя, которое он должен менять без правки кода; это валидация ввода примитива мутации.
- **Q2 — новый класс артефактов?** Неприменим (Q1 = нет). Ни `exo__Class`, ни `exo__Property` не
  вводятся, новых SPARQL-вопросов не появляется ⇒ по decision-rule `/onto-rfc` это **не** onto-RFC,
  а обычное требование к поведению CLI. Профиль прогнан целиком, вывод записан.
- **Q3 — под какое из трёх исключений попадает TS-реализация?** **(в) инфраструктурные guard rails**:
  правило обеспечивает **корректность структуры графа** (мусорный ключ в него не попадает), а не
  описывает домен пользователя. Граница CLAUDE.md («как должна быть валидна сама структура графа»)
  проходит ровно здесь.

### Q3-addendum — долг гомоиконичности в СОСЕДНЕМ коде (назван, этим req НЕ чинится)

`packages/cli/src/commands/propertyMutationShared.ts` держит `GUARDED_PROPERTIES` / `GuardedRoute` —
**хардкод-зеркало** того, что граф уже декларирует: какие `exocmd__Command` владеют свойством и какие
из них его **снимают**. Q1 по нему = **ДА** (набор команд пользователь меняет ассетами vault, не
правкой кода) ⇒ это долг гомоиконичности, а не законное исключение.

Цена названа в докстринге самого модуля: таблица «does NOT make “a listed cliName exists in the
user's vault” checkable in CI … that is a separate follow-up» — то есть она может разъехаться с графом
при переименовании команды апстримом, и это **уже случалось** (`archive-completed` → `archive`).
⇒ Вынесен отдельным тикетом на доску; в scope этого req не входит.
