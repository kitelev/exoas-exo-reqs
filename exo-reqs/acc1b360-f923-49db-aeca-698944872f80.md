# req(exo): CLI query-result cache bounds its own growth (eviction) + `cache clear`/`cache stats`

## Job Story

When I run many distinct SPARQL queries over time, I want the CLI's query-result cache
(`~/.exocortex/cache/query-results/`) to bound its own size instead of growing to hundreds
of megabytes of regenerable files — and when I do want to reclaim the space immediately, I
want a first-class `exocortex cache clear` command rather than a hand-typed `find … -delete`.

## Statement (Gherkin)

```gherkin
Given the query-result cache is at its entry-count or total-size cap
When QueryResultCache.set writes a new entry that pushes it over the cap
Then the oldest entries are evicted (oldest-first, by mtime) until both count and size are back within cap
And the entry just written is never evicted
And a prune failure never fails the set

Given a populated query-result cache
When I run `exocortex cache clear`
Then every cached query result is removed and the count/bytes freed are reported

Given a populated query-result cache
When I run `exocortex cache stats`
Then the current entry count and total size are reported
```
