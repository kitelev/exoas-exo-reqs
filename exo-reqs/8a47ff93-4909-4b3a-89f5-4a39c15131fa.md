# req(exo): a `life__Episode` whose period contains today renders a 📍 marker, via a registered `isEpisodeOngoing` display-matcher host function

> Follow-up of req `[[d6cd2371-bdf2-460e-840e-841480273869]]` (the host-function matcher capability) and of the `life__Episode` display line. The class already renders `<label> · <start> · <end>` through a plain `exo__DisplayNameSpec`; what it cannot express is **"this period contains today"**, because that is a computed temporal predicate, not a frontmatter-value equality.

## Job Story

When I scan a list of episodes, I want the one I am **living right now** to stand out without reading dates — so that "where am I currently" is answered by looking, not by comparing three date strings against today.

## Context

`exo__DisplayNameSpec` supports two matcher kinds today: value-equality (`matchPath`/`matchValue`, req `ed4201d1`) and host-function (`matchHostFunction`, req `d6cd2371`). "Ongoing" is unreachable by the first — it compares the instance's own dates against **now**, a value no frontmatter carries. So it belongs to the second kind, exactly like `isEffortBlocked`.

The registry (`DEFAULT_DISPLAY_MATCHER_HOST_FUNCTIONS`, `displayMatcherHostFunctions.ts`) is currently seeded with a single entry. Its signature is `(app, metadata) => boolean` — **no parameter channel**, so a host function hardcodes the property names it reads, as `isEffortBlocked` hardcodes `ems__Effort_blocker`. This req follows that precedent rather than widening the signature.

Unlike `isEffortBlocked`, this predicate is **not cross-asset**: it reads only the rendered instance's own `life__Episode_start` / `life__Episode_end`. It is nonetheless a host function because the comparand (today) is ambient, not declarative.

## Statement (Gherkin)

```gherkin
Background:
  Given a registered display-matcher host function "isEpisodeOngoing"
    And "today" is the LOCAL calendar date (local getters, never toISOString/UTC —
        the local-basis established by reqs 5c47471a / 26d79c70 / 96be4042)
    And date values are compared as their first 10 characters (YYYY-MM-DD),
        so a value carrying a time component compares by its calendar day

Scenario: the period contains today → the spec participates
  Given a life__Episode with life__Episode_start on or before today
    And life__Episode_end on or after today
  When the plugin resolves its displayName
  Then "isEpisodeOngoing" returns true
    And a spec naming it participates → its 📍 prefix composes ahead of the
        base period spec (priority 200 vs 100) → "📍 <label> · <start> · <end>"

Scenario: an OPEN period (no end) that has started counts as ongoing
  Given a life__Episode with a start on or before today and NO life__Episode_end
  When the plugin resolves its displayName
  Then "isEpisodeOngoing" returns true → "📍 <label> · <start>"
    (the absent end is collapsed by exo__DisplayNameSpec_separator)
  # An episode left open long after it really ended therefore stays marked.
  # That is intended: the marker doubles as a "you forgot to close this" signal.

Scenario: a period entirely in the past or the future → no marker
  Given a life__Episode whose end is before today, OR whose start is after today
  When the plugin resolves its displayName
  Then "isEpisodeOngoing" returns false
    And the base period spec alone renders → "<label> · <start> · <end>"

Scenario: boundary days are INCLUSIVE
  Given a life__Episode whose start is exactly today
    Or whose end is exactly today
  Then "isEpisodeOngoing" returns true

Scenario: a malformed or absent start is not ongoing (fail-closed)
  Given a life__Episode with no life__Episode_start, or an unparseable one
  Then "isEpisodeOngoing" returns false
    And no 📍 is rendered
  # An asset that cannot be judged must not claim to be happening now.

Scenario: the verdict is per-render, never baked into the compiled template
  Given the 📍 spec was loaded once via scanVault
  When the calendar day advances past the episode's end
  Then a re-resolve no longer participates — no re-scan required

Scenario: no regression for every other class
  Given any asset that is not a life__Episode, or a spec with no matcher
  Then selection and rendering are byte-identical to today
```

## Acceptance Criteria (Definition of Done)

- `isEpisodeOngoing` is present in `DEFAULT_DISPLAY_MATCHER_HOST_FUNCTIONS` and resolvable by name from an `exo__DisplayNameSpec_matchHostFunction`.
- A component test drives the REAL `scanVault → getTemplateForClass(metadata) → DisplayNameResolver.resolve` over an in-memory vault carrying the 📍 spec, running the REAL predicate (no hand-injected matcher result), and asserts all five outcome scenarios above.
- **Revert-verified**: neutralizing the predicate to never-participate turns the ongoing cases RED; to always-participate turns the past/future cases RED; restore → all GREEN. The non-episode regression case stays GREEN under both reverts (negative control, proving the delta is exactly the episode-marker case).
- Timezone-independent: the test fixes the clock so the verdict does not depend on the runner's zone (`installFakeOffsetDate` — `process.env.TZ` is not re-tzset under jest).
- The live 📍 `exo__DisplayNameSpec` (priority 200, one `exo__PrintedLiteral` "📍 ") is authored as vault data in `exoas-public/life/`, SHACL-clean, and composes with the existing base spec `b836acf7`.

## Alternatives

- **A materialized `life__Episode_ongoing: true` property instead of a computed predicate.** Rejected: nothing would flip it when the calendar advances, so it would silently rot — the precise failure the "graph record outlives its referent" lesson describes. A period's ongoing-ness is a function of now, not a fact to store.
- **Widen the host-function signature with a parameter channel** (so one generic `isPeriodOngoing` could serve any `_start`/`_end` pair). Rejected for this req as a larger engine change; noted as the natural extension the moment a second period-like class wants the same marker. The current precedent (`isEffortBlocked`) hardcodes its property names too.
- **Reuse 🔄 (the Doing marker).** Rejected: it already means an `ems__Effort` in progress; sharing the glyph across two unrelated axes makes a list ambiguous.

## Метрики успеха

- Живой эпизод, содержащий сегодняшний день, показывает 📍 во всех восьми поверхностях displayName без правки рендереров.
- 0 новых SHACL violations после авторинга спеки.
- 0 регрессий: остальные классы и спеки без матчера рендерятся байт-в-байт как прежде.
