# Contract

Pearson correlation and least-squares regression over two bound columns, without
leaving SPARQL. Until now these had to be done in Python — the analytics that
surfaced this (breakfast time-of-day vs wake-up) could not be expressed at all.

Accumulation is **single-pass and O(1) in group size**: six running sums
(n, Σx, Σy, Σx², Σy², Σxy). No pair is retained, unlike `agg:median`.

## Given/When/Then

**Scenario: a perfect increasing line is recovered exactly**
- Given pairs on `y = 2x + 1` for x = 1..5
- When `agg:corr(?x, ?y)` / `agg:slope(?x, ?y)` / `agg:intercept(?x, ?y)` are selected
- Then they return 1, 2 and 1 respectively

**Scenario: direction is preserved**
- Given pairs on `y = -x + 10`
- Then corr = -1, slope = -1, intercept = 10
- (a one-column fallback cannot fake the SIGN — ignoring ?y makes all three depend on
  ?x alone and loses direction entirely)

**Scenario: a pair is counted only when BOTH columns are numeric**
- Given a solution where ?y is unbound or non-numeric
- Then that pair is skipped — it must not shift the ?x-only sums

**Scenario: an undefined answer is NaN, never 0**
- Given n < 2, or either column constant (zero variance)
- Then the aggregate returns `NaN`^^xsd:double
- And NOT 0 — "measured, no correlation" is a different and false claim from
  "the question has no answer"

**Scenario: arity is a property of the aggregate**
- Given `agg:median` (1 column) and `agg:corr` (2 columns)
- When either is called with the wrong number of arguments
- Then translation raises, naming that aggregate's own arity
- (this generalises req 0a8977bb, which pinned a hard "exactly 1")

**Scenario: single-column aggregates are untouched**
- Given `agg:median(?x)`
- Then the result is identical to before this requirement

## Deliberate divergence

Single-column aggregates in this file return 0 on empty input. For a median 0 is
arbitrary; for a correlation it is a specific WRONG finding a reader would act on.
A truly unbound result is not expressible (`finalize` must return a Literal; an empty
one throws), so NaN^^xsd:double is the honest encoding available.
