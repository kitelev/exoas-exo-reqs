## Job story

When I run `apply rename-to-uid` on a note whose basename carries a YAML-significant character — a leading `-`, a `: `, a ` #`, an interior `"` or `\` — I want the old basename to land in `aliases` (and in `exo__Asset_label` when the label was empty) as a correctly escaped YAML scalar, so the file stays parseable and the alias equals the basename byte-for-byte; and I want a basename with no such character to keep the plain form it has today (no quote churn across the corpus). The same guarantee holds for the batch `update-label` writer (batch writer withdrawn 2026-09-17, see Non-goals).

## Context

- Source: ticket `77ffc37a-cdb6-4f56-bce7-af5b47d32e7b` (LOW-2 of the ORCH review of PR kitelev/exocortex#4250; parent techbacklog `bbac67ce`). Same defect class as ticket `4f226028` / req `f7790000-3779-4bbb-8bbb-000000000002` (`apply set-label` → `property_append`), which this req does NOT amend: that req governs the grounding path, this one governs the two remaining hand-built writers (batch writer withdrawn 2026-09-17, see Non-goals — one writer remains).
- Mechanism, round 2 (review of PR #4256, MEDIUM + LOW-2): every `.replace(pattern, <string built from the basename>)` in the same service — the whole-frontmatter splice and the four aliases branches that use `.replace` — read `$1` / `$&` / `$$` in the basename as a JavaScript replacement pattern before the YAML escaper saw the text (`Pay $100 invoice` → a capture spliced in, frontmatter unparseable at rc 0; `Cost $$ total` → `Cost $ total`, silent); and the block-list append replaced the FIRST occurrence of the block text, editing an identical `tags:` list placed earlier. Fix: function replacers (`() => …`) at all four `.replace` sites plus the frontmatter splice, and the block append splices by the match position. Same class as `FrontmatterService.updateProperty` (#3795 H1).
- Mechanism (`packages/core/src/services/RenameToUidService.ts` @ `ee315fc8`): six interpolation sites write the basename bare — `exo__Asset_label: ${basename}` (`:63`, label empty) and five `aliases` branches (`:85` no aliases, `:110` append to a block list, `:124` empty inline `[]`, `:140` non-empty inline `[…]`, `:148` `aliases:`/`null`/`~`). The dedup (`:103`, `:135`) compares the RAW list text with the plain basename, so an alias already stored quoted (the shape `apply set-label` writes) is appended a second time. `packages/cli/src/executors/BatchExecutor.ts:539-542` `executeUpdateLabel` wraps the label in `"…"` without escaping `"` / `\` (the command has had no CLI consumer since v16.0, #3130; fixed for class-completeness).
- Observed on the published CLI 16.240.9 (temp vault, 9 basenames): `rename-to-uid` returns rc 0 «✅ File renamed to UID» in every case; `- leading dash` and `Note: colon space` leave the whole frontmatter unparseable (js-yaml + PyYAML), `Tag #hash` parses with alias AND label truncated to `Tag`, and a `: `-basename appended to an existing list parses as a MAPPING item (`{Note: "with list"}`) instead of a string.
- Design (plan-gate, ORCH `main-35699` 2026-09-17 plan-ok): one escaper per site policy that PRESERVES the on-disk shape — block/scalar sites quote-when-needed (`needsYamlQuoting(v, true) || isCompleteDoubleQuotedScalar(v) ? quoteYamlString(v) : v`; corpus 2026-09-17: 26 634 plain vs 8 189 quoted alias items, 0 inline arrays), the flow-context site (`:140`) and the batch writer always `quoteYamlString` (their existing shape is already quoted / flow context reserves `,[]{}`); dedup compares `decodeYamlQuotedScalar(item)`.

## Non-goals

- Not changing `apply set-label` / `property_append` / `property_set` (req `f7790000-3779-4bbb-8bbb-000000000002`) or the `create` path (`serializeYamlScalar`, #3748/#3750).
- Not re-quoting existing alias items on disk and not converting inline arrays to block lists — only the item this service adds is escaped; the surrounding shape is preserved.
- `BatchExecutor` (consumer-less since CLI v16.0 #3130) deleted by ticket `99a904a9` / PR kitelev/exocortex#4260 (2026-09-17) — the two batch update-label scenarios above are WITHDRAWN with it; not restoring a `batch` CLI verb.
- Not changing which characters `needsYamlQuoting` treats as significant (shared helper untouched); the flow-context site side-steps it by always quoting.
