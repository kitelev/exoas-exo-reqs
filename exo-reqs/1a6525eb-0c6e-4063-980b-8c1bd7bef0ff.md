## Job Story

Когда я объявляю displayName для класса, у части инстансов которого необязательные поля пусты, я хочу объявить **разделитель** и **формат значения** прямо в vault-ассетах, чтобы имя читалось как список непустых полей с человеческой датой — и чтобы менять это без релиза плагина.

## Scenario 1 — разделитель схлопывается вместе с пустой частью

```gherkin
Given an exo__DisplayNameSpec declaring exo__DisplayNameSpec_separator " · "
  And its ordered parts print rating, dish, place and timestamp
When an instance has NO rating
Then the rendered displayName starts with the dish — there is no leading " · "
When an instance has NO timestamp
Then the rendered displayName ends with the place — there is no trailing " · "
When an instance has neither rating nor timestamp
Then exactly one " · " separates the two surviving fields
When a rendered VALUE itself contains " · "
Then that value is NOT split — the field boundary comes from the TEMPLATE, not the rendered text
```

## Scenario 2 — формат значения (дата)

```gherkin
Given an exo__PrintedProperty declaring exo__PrintedProperty_format "DD.MM"
  And it prints exo__Event_timestamp
When the stored value is the ISO string "2026-01-31T13:28:20"
Then the part renders "31.01"
When the stored value is a Date parsed from a zone-less YAML timestamp
Then the part renders the SAME literal digits — no timezone shift, no quotes, no ".000Z"
When the stored value is not a recognisable date
Then the value is printed UNCHANGED (fail-open — never empty, never an exception)
When the format needs a component the value does not carry (e.g. HH over a date-only value)
Then the value is printed UNCHANGED — the engine never fabricates zeros
```

## Scenario 3 — байт-идентичность живого корпуса (регрессионный якорь)

```gherkin
Given the 39 live displayName assets (11 exo__DisplayNameSpec + 15 exo__PrintedProperty + 13 exo__PrintedLiteral)
  And none of them declares a separator or a format
When the real engine renders every real instance of every specified class
Then every compiled template and all 174 rendered names are BYTE-IDENTICAL to the pre-change run
```

## Scenario 4 — композиция не теряет разделитель

```gherkin
Given two participating specs over one note
  And the higher-priority spec contributes only a prefix marker
  And the lower-priority spec contributes the core AND declares a separator
When the displayName is composed
Then the composed name keeps the prefix marker AND the core's separator semantics
```

## Обоснование «один req, два механизма»

Разделитель и формат — независимые механизмы, но **один наблюдаемый исход** (имя подачи вида `6.5 · Панкейки · Teplo · 31.07` невыразимо без обоих), **одни и те же два файла** движка, **один onto-RFC** и **одна пара TBox-свойств одного семейства**. Разбиение на два req/PR удвоило бы CI-циклы и сделало бы второй PR зависимым от первого, не добавив наблюдаемой ценности. Инвариант «каждая фича — своей осью revert-verify» соблюдается внутри одного PR: нейтрализация интерпретатора разделителя роняет только тесты схлопывания, нейтрализация интерпретатора формата — только тесты формата.

## Acceptance Criteria — две НЕЗАВИСИМЫЕ оси revert-verify

Единая req-запись не должна размывать трассируемость: каждая фича обязана падать **своей** осью, а вторая при этом остаётся зелёной (доказательство не-vacuous покрытия).

- **AC-A (ось «разделитель»).** Нейтрализация интерпретатора разделителя (`renderWithSeparator` → прежний одиночный проход) роняет **только** тесты схлопывания (ведущий/хвостовой/двойной разделитель, отсутствие висячего `·`). Тесты формата и байт-идентичности остаются ЗЕЛЁНЫМИ.
- **AC-B (ось «формат»).** Нейтрализация интерпретатора формата (`applyValueFormat` → всегда `null`) роняет **только** тесты формата (`DD.MM` над ISO-строкой и над `Date`, fail-open). Тесты схлопывания и байт-идентичности остаются ЗЕЛЁНЫМИ.
- **AC-C (байт-идентичность).** Прогон реального движка над 39 живыми displayName-ассетами и всеми 174 инстансами специфицированных классов — побайтово идентичен пред-изменениям. Проверяется прогоном, не рассуждением.
- **AC-D (композиция).** Спека с разделителем, участвующая в композиции с prefix-спекой, сохраняет и маркер-префикс, и семантику разделителя (разделитель берётся у спеки, давшей ядро).
