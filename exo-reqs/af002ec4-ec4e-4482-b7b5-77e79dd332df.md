## Job Story

Когда ExoSync проверяет, изменился ли репозиторий, я хочу, чтобы **неизменившийся** ответ не
тратил квоту GitHub — потому что по документации `304 Not Modified` не списывается с primary
rate limit, а сейчас каждый холостой прогон платит полную цену за ответ, который он уже знает.

## Замеренная мотивация (2026-09-26, считающий прокси + заголовки живых ответов)

- Холостой `exosync-parity` на 21 репозиторий = **83 запроса**, и **все 83** — `git/refs` +
  `git/commits` + `git/trees`, то есть ровно те чтения, которые на неизменившемся репозитории
  обязаны отдавать `304`.
- **Доказано исполнением** (приёмка с красным исходом уже предъявлена):
  `25 запросов с If-None-Match → коды {304: 25} → x-ratelimit-used +7` (это фон ~25/мин);
  `25 тех же без него → {200: 25} → used +24`. Контроль показывает, что прибор умеет краснеть.
- **ETag отдаётся на ВСЕХ трёх классах чтений** — проверено отдельно на каждом эндпоинте:
  `git/refs/heads/main` → `304`, `git/commits/{sha}` → `304`, `git/trees/{sha}?recursive=1` → `304`.
  Оговорки «а вдруг на refs ETag нет» не остаётся.
- В коде на момент написания: `If-None-Match` / `ETag` — **0 вхождений**.

## Statement (Gherkin)

```gherkin
Feature: условные запросы (ETag / If-None-Match) на head/tree/commit-чтениях

  Scenario: неизменившийся репозиторий не тратит квоту
    Given ExoSync сохранил ETag предыдущего ответа для данного эндпоинта
    When тот же эндпоинт запрашивается снова, а на remote ничего не менялось
    Then запрос уходит с заголовком If-None-Match
    And GitHub отвечает 304
    And primary-квота за этот запрос не списывается

  Scenario: изменившийся репозиторий обрабатывается как раньше
    Given ETag сохранён, но на remote появился новый коммит
    When эндпоинт запрашивается с If-None-Match
    Then GitHub отвечает 200 с новым телом и новым ETag
    And ExoSync применяет изменения ровно как без условного запроса

  Scenario: отсутствующий ETag не ломает синк (fail-open)
    Given для эндпоинта ETag ещё не сохранён либо сервер его не прислал
    When выполняется чтение
    Then запрос уходит безусловным
    And синк отрабатывает штатно

  Scenario: ETag не путается между репозиториями
    Given сохранены ETag для двух разных репозиториев
    When читается любой из них
    Then используется ETag именно этого репозитория
```

## Non-goals (out of scope этого требования)

- **Кэш неизменяемых объектов по SHA** — отдельный механизм (issue #4410, req `086df113`):
  условный запрос всё равно **идёт по сети** и стоит точку в secondary-бюджете, а кэш снимает
  сам запрос. Механизмы дополняют друг друга: ETag нужен для **mutable** `refs`, кэш — для
  **immutable** `commits`/`trees`/`blobs`.
- **Параллелизм `syncAll`** (#3911) — повышает мгновенную ставку запросов и работает ПРОТИВ этой
  экономии; делать только ПОСЛЕ.
- **Secondary-бюджет**: `304` по-прежнему стоит 1 точку из 900/мин — это требование снимает
  primary-цену, не secondary.

## Приёмка (красный исход назван явно)

1. Повторить серию A/B (25 условных против 25 безусловных) **через транспорт CLI**, а не curl:
   условная серия по приросту `x-ratelimit-used` обязана быть неотличима от фона.
   ⛔ Красный: прирост сопоставим с безусловной серией.
2. `restCalls` из `SyncPhaseTimer` на **втором подряд** холостом синке падает с 81 до
   **≤ числа репозиториев** при неизменном вердикте синка.
   ⛔ Красный: `restCalls` не изменился либо вердикт синка поехал.
