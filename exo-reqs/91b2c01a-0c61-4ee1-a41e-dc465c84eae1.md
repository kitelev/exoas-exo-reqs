# req(exo): the CLI's own git calls ignore the enclosing repository's GIT_* environment (a git hook of another repo cannot redirect them)

## Job Story

When `exocortex-cli exosync sync` runs inside a git hook of some OTHER repository (a pre-commit that syncs the vault, a CI step), I want the CLI's own read of the vault's submodule state to look at the VAULT's repository — not at the repository whose hook is running — so the 3-way merge gets its genuine base instead of silently falling back to a full conflict.

## Statement (Gherkin)

```gherkin
Given a vault that is a git repository with a real submodule at assetspaces/o/r checked out at commit C
And the process environment carries GIT_DIR and GIT_INDEX_FILE of an unrelated decoy repository (as git exports them inside that repository's hook)
When the exosync base-SHA provider (nodeLocalBaseShaProvider) resolves assetspaces/o/r
Then it returns C
And the decoy repository is unchanged (same HEAD, same index bytes)

Given every place in packages/cli/src that runs the `git` binary
Then each call either passes an environment with git's repository-local variables removed (git rev-parse --local-env-vars)
Or is on a named allow-list of calls that inherit the environment ON PURPOSE, with the reason next to it
  (validate-schema getStagedMdFiles: `git diff --cached` must read the committing repository's index, including the temporary GIT_INDEX_FILE of a partial commit)
```

## Why

Measured 2026-09-26 on a throw-away fixture: `GIT_DIR=<decoy>/.git GIT_INDEX_FILE=<decoy>/.git/index git -C <vault> submodule status assetspaces/o/r` prints `pathspec 'assetspaces/o/r' did not match any file(s) known to git` — the provider would return null, and the engine would run its conservative full-conflict fallback for a space whose base is known. `-C` changes the directory; GIT_DIR still names the repository.

The list of variables is git's own (`git rev-parse --local-env-vars`, 16 on git 2.33): the ones git itself clears when it runs a command in another repository. The test-side counterpart is `packages/test-utils/src/jest/stripRepoGitEnv.cjs` (PR #4380); the plugin has its own `GitSubmoduleOps.stripGitEnv`.

## Binding

Integration: `packages/cli/tests/unit/commands/exosync-sync.test.ts` (real git fixture + decoy repository) and a source scan over `packages/cli/src` for the allow-list rule. Origin: task 9cf206cd, part 2.
