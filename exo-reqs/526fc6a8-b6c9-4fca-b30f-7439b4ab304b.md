# req(exo): ExoSync R5 secret-scan — per-file skip + redacted quarantine, not whole-repo refuse (RFC 6a1a6518 / secret-scan, #3976)

> Source: RFC `6a1a6518-613c-447c-a75b-9d30f4ae3008` (Approved) — ExoSync perf & rate-limit revision. This requirement is the **secret-scan / #3976** deferral, flagged by the RFC's contrarian reviewer as the **actual first blocker** of the incident that motivated the whole RFC.
>
> **Why it matters:** R5's whole-repo refuse means a single credential in ONE file blocks the entire repo push (`pushed 0`) — every clean file in the changeset is held hostage. Empirical 2026-07-27: 2 PAT-bearing files blocked 915 legit files of `exoas-shared-private`. Per-file skip preserves the exact same security floor (the secret still never ships) while letting the clean files through.
>
> **⛔ Security floor (unchanged):** a file matching a secret shape is REMOVED from the push — the raw secret reaches the remote in neither the whole-repo nor the per-file path. Skipping achieves the floor even if quarantine is unavailable.

## Job Story

When ExoSync would push a changeset and one file has accidentally-pasted credential in it, I want ONLY that file held back (with a durable redacted copy quarantined and a clear warning to revoke the token), so the rest of my changeset still syncs instead of the whole repo being blocked — while the secret still never leaves my device.

  Given the same changeset

  Then a quarantine entry exists for file B

## Design notes

- **Skip = security floor.** Removing the offending path from `pushFiles` means the secret is not in the commit regardless of whether the quarantine sink is present or succeeds. Quarantine is for the user's durable redacted record, not for the floor.
- **Dedup across D16 retries.** `runPushLoop`'s while loop rebuilds `pushFiles` from `pushFilesAll` each iteration, so the offending file reappears and is re-skipped every attempt; a `handledSecretPaths` set ensures it is quarantined exactly once.
- **Decoupled flush.** Secret entries flush via a SEPARATE `flushQuarantine` call so the `flushed` boolean that gates the D18 resolved-remote-wins withhold logic is unaffected (secret entries never drive a destructive apply).
- **No message-parser risk (`error-enrich-preserve-message`):** the secret detail is a `RepoSyncResult` field, never a thrown `Error` — none of `isNonFastForwardError` / `isRateLimitError` / `isAuthError` classify it.
- **Partial ship is sanctioned:** a transient dangling ref to the skipped asset (until its secret is removed + it re-derives) mirrors the existing quarantine path's transient partial-ship. The `redactSecrets` used here already exists (secretScan.ts).
