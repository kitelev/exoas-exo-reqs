## Контекст

`validate schema --shapes-mode` перечисляет violations полностью — с focusNode, конструктом и
целью. Warnings он сводит в **одно число**:

```
ℹ️  550 warning(s) (550 unresolvable class/symbolic ref(s) — not validated) — these do not affect the exit code.
```

Число меняется после каждого крупного `exosync pull`, и вопрос «что именно изменилось» штатным
выводом не решается: список есть только в `--format json` (`data.warnings[]`) и `--format earl`
(`dc:description`), про которые ни `--help`, ни сам вывод не намекают.

⚠ Наблюдённая цена (2026-08-08): прирост warnings в vault-tbank был списан на «ссылки на
несмонтированные в профиле **классы**». Замер показал обратное — классы как раз смонтированы, а
нерезолвимы **инстансы данных** из ассетспейса вне профиля. Неверное объяснение прожило бы в
durable-правиле, если бы не отдельный разбор через JSON.

Замер `[vault-exodev, 2026-09-24 12:48 +05, CLI 16.251.0]` — **550 warnings, 0 violations**:

| Причина | Кол-во |
|---|---|
| Цель отсутствует в этом vault (bare file-IRI `obsidian://vault/<uuid>.md` без пути) | 546 |
| Цель — symbolic-IRI свойства/класса (`https://…/ems#Effort_votes`) | 4 |
| Цель смонтирована, но тип не резолвится (file-IRI **с** путём) | 0 |
| term-IRI collision (req `00e8079e`) | 0 |

Дискриминатор **проверен исполнением, а не выведен**: 233 уникальные bare-цели сверены с индексом
имён файлов vault-exodev (34 775 `.md`, один обход) — на диске **0 из 233**, то есть «bare» ⇒
«цели нет в этом vault» истинно, а не структурный артефакт. Канарейка: заведомо существующий uid
в том же индексе найден.

⛤ Принцип, на котором стоит это требование, — **дословная цитата двух Active-req соседей** по той
же поверхности: «Skip totals are always printed so `0 violations` never masks `nothing was actually
checked`» (`c23f6f50`, audit ontology-membership) и «Skip-accounting is always printed so
`0 violations` never masks foreign-skipped ontologies» (`df6c979e`, audit ontology-url). У
`validate schema` этого паритета нет. Более того, тот же аргумент уже применён внутри самой команды
к ОДНОЙ подкатегории — комментарий у collision-блока: «the condition was previously INVISIBLE;
reporting it only as a few extra units inside a several-hundred-warning aggregate would leave it
just as invisible on the default surface» (req `00e8079e`). Это требование обобщает его на все
причины.

## Границы (несущие, не косметика)

- **Полный список не печатается.** 550 строк на штатной поверхности — шум; списки остаются за
  `--format json` и `--format earl`. Печатается только сводка «причина → счёт».
- **Машинные форматы не меняются.** `--format json` и `--format earl` обязаны остаться
  байт-идентичными: у них список уже есть, и потребители на него завязаны.
- **Блок term-IRI collision не трогается.** Он принадлежит req `00e8079e` и уже печатает и счёт,
  и сами IRI. В сводке эта причина присутствует одной строкой; детали остаются его блоком —
  двойного перечисления быть не должно.
- **Классификация не меняет ни `conforms`, ни exit-code.** Warnings как не влияли на код возврата,
  так и не влияют.
- Категория «причина не определена» существует **обязательно**: сумма по причинам обязана быть
  равна общему счёту при любом входе, в том числе на форме цели, которой сегодня нет в корпусе.

```gherkin
Feature: validate schema names the REASONS behind its warning counter

  Scenario: the text report breaks the warning total down by reason
    Given a vault whose run yields warnings of more than one reason
    When I run `exocortex validate schema --shapes-mode`
    Then the text output lists every non-empty reason with its own count
    And the sum of the per-reason counts equals the total warning count

  Scenario: a target absent from this vault is told apart from one that is present
    Given a warning whose target is "obsidian://vault/<uuid>.md" with no path segment
    And another warning whose target is "obsidian://vault/assetspaces/<...>/<uuid>.md"
    When I run `exocortex validate schema --shapes-mode`
    Then the two are counted under DIFFERENT reasons
    And the first reason names the target as absent from this vault

  Scenario: a symbolic IRI target is its own reason
    Given a warning whose target is "https://exocortex.my/ontology/ems#Effort_votes"
    When I run `exocortex validate schema --shapes-mode`
    Then it is counted under the symbolic-IRI reason
    And not under the absent-target reason

  Scenario: an unrecognised target shape still balances the sum
    Given a warning whose target matches no known shape
    When I run `exocortex validate schema --shapes-mode`
    Then it is counted under an explicit "reason not determined" line
    And the sum of the per-reason counts still equals the total warning count

  Scenario: no warnings means no breakdown
    Given a vault that yields zero warnings
    When I run `exocortex validate schema --shapes-mode`
    Then no breakdown line is printed

  Scenario: machine formats are untouched
    Given the same vault
    When I run the command with `--format json` and with `--format earl`

```

## Приёмка

- **Revert-verify:** нейтрализовать классификатор → сценарии 1-4 RED, сценарии 5-6 GREEN;
  вернуть → все GREEN. Счётчик-строка при нейтрализации остаётся — исчезает только разбивка.
- **Ось доходит до конечного эффекта:** проверяется **напечатанный текст** текстовой ветки, а не
  внутренняя структура. Ось на JSON-ветку вакуумна по построению — она эти данные уже несёт.
- **Прогон на живом vault:** `vault-exodev` воспроизводит 550 = 546 + 4, `violationCount` 0,
  `conforms` не меняется.
- **Контроль обратной совместимости:** `--format json` и `--format earl` на том же vault дают
  вывод, побайтно равный выводу предыдущего релиза.
